## Business rules

- Receipts are mapped to company codes via dictionary `bk` mapping 'DB-4471' to 'DK01', 'HDFC-0932' to 'IN02', 'DBS-1180' to 'SG01', and 'JPM-2290' to 'US01'. [C4:L4](#c4-l4) [C7:L2-3](#c7-l2-3) ✓
- Open item records are excluded if their `cust_no` belongs to `EXCL`, which contains 'C10077' and 'C10412'. [C4:L5](#c4-l5) [C8:L6](#c8-l6) ✓
- Reference extraction `get_refs` identifies 8-digit strings starting with 9 using regular expression `(?<!\d)(9\d{7})(?!\d)`. [C10:L16](#c10-l16) [C10:L18](#c10-l18) ✓
- Receipt customer assignment prioritizes manual override 'OV', followed by reference match 'REF', and name match 'NM'. [C14:L2-6](#c14-l2-6) ✓
- Exact matching applies when open invoice balance matches remaining receipt amount within tolerance `EX_TOL` of 0.01 and invoice is undisputed. [C4:L3](#c4-l3) [C26:L20](#c26-l20) ✓
- FIFO allocation iterates through undisputed positive balance invoices in descending order of current balance. [C26:L34-35](#c26-l34-35) ✓
- Write-offs `WO` clear open balances on touched documents if the remaining balance is greater than 0.005 and less than or equal to `TOL`. [C26:L48-50](#c26-l48-50) ✓
- Residual receipt amounts greater than 0.005 are classified as 'UNAPP' when customer is known, or 'SUSP' when unknown. [C30:L13-17](#c30-l13-17) ✓

- *inference* · Function `apply_fifo` sorts invoices by `-bal[d]`, meaning allocation applies largest-balance first rather than by invoice due date. [C26:L35](#c26-l35) ✓
- Function `alloc_by_aging` defined at Cell 23 lines 1 through 20 is never called. [C23:L1-20](#c23-l1-20) ✓
- *risk* · All receipt and open invoice data is brought into single-node driver memory via `toPandas`, creating an out-of-memory risk as transaction volume scales. [C24:L1-2](#c24-l1-2) ✓
- *risk* · Reconciliation break checks only print warning messages to standard output and do not abort the run. [C34:L5-7](#c34-l5-7) [C41:L7-8](#c41-l7-8) ○
