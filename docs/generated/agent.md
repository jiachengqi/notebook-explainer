## Invariants

- For every receipt, non-write-off line amounts in receipt currency (`amt_rc`) must sum to the original receipt amount `amt`. [C34:L1-4 (file L421)](#c34-l1-4) ✓
- The rounding adjustment in cell 32 ensures that any minor discrepancy between `amt_rc` sum and receipt `amt` is applied to the final non-WO line. [C32:L6-7 (file L402)](#c32-l6-7) ≈
- Invoice balances stored in `bal` must never become negative. [C26:L52-56 (file L337)](#c26-l52-56) ✓
- Invoices flagged with `dispute == 1` are excluded from `EXACT` and `FIFO` allocations. [C26:L20 (file L305)](#c26-l20) [C26:L34 (file L319)](#c26-l34) ≈
- Receipt lines cannot allocate more than the remaining open balance of an invoice. [C26:L11 (file L296)](#c26-l11) [C26:L25 (file L310)](#c26-l25) [C26:L39 (file L324)](#c26-l39) ○
- Receipts with unresolved customer mappings are routed to `SUSP` rather than `UNAPP`. [C30:L14-17 (file L379)](#c30-l14-17) ✓
- Company-level receipt totals must reconcile with line totals across all companies. [C41:L1-8 (file L501)](#c41-l1-8) ○

## Risky areas

- `TOL` is initialized to 0.5 but then reassigned to 5.0 in cell 29. [C4:L1 (file L33)](#c4-l1) [C29:L4 (file L361)](#c29-l4) ✓
- *risk* · Changing `TOL` affects both the threshold to trigger `apply_fifo` and the write-off threshold in `do_wo`. [C26:L48 (file L333)](#c26-l48) [C29:L4 (file L361)](#c29-l4) [C30:L10 (file L375)](#c30-l10) ✓
- *risk* · Matching reference numbers by `first('cust_no')` arbitrarily chooses a customer if multiple open items share the doc number. [C13:L1-3 (file L124)](#c13-l1-3) ✓
- *risk* · Deduplicating `x2` by `dropDuplicates(['rcpt_id'])` arbitrarily selects a customer when payer names match multiple aliases. [C13:L5-6 (file L128)](#c13-l5-6) ✓
- *risk* · In `apply_fifo`, invoices are sorted by `-bal[d]`, which allocates largest balances first instead of true first-in-first-out by date. [C26:L35 (file L320)](#c26-l35) ✓
- *risk* · Discrepancy check `bad` only prints warnings and does not interrupt execution or fail the job. [C34:L4-7 (file L424)](#c34-l4-7) ✓
- *risk* · Company reconciliation break check only prints a message without halting execution. [C41:L7-8 (file L507)](#c41-l7-8) ○
- *risk* · The notebook exit status always reports `"status": "ok"` regardless of reconciliation breaks. [C47:L1 (file L551)](#c47-l1) ✓
- *risk* · `notify_ar` and `log_run` execute even when `dry == "Y"` and tables were not written. [C37:L1-5 (file L458)](#c37-l1-5) [C43:L11 (file L532)](#c43-l11) [C44:L1 (file L536)](#c44-l1) ✓

## Do not change without approval

- The excluded customer list `EXCL` contains `"C10077"` and `"C10412"`. [C4:L5 (file L37)](#c4-l5) [C8:L6 (file L72)](#c8-l6) ✓
- The bank account to company code mapping `bk` maps four specific bank accounts. [C4:L4 (file L36)](#c4-l4) ✓
- Exact match tolerance `EX_TOL` is set to 0.01. [C4:L3 (file L35)](#c4-l3) [C26:L20 (file L305)](#c26-l20) ✓
- Table `fin_cash.alloc_lines` is overwritten using `mode("overwrite")` and `overwriteSchema` enabled. [C4:L6 (file L38)](#c4-l6) [C37:L1-2 (file L458)](#c37-l1-2) ✓
- Table `fin_cash.open_items_after` is overwritten using `mode("overwrite")`. [C38:L8-9 (file L473)](#c38-l8-9) ✓
- Table `fin_cash.ar_aging_snap` is appended to using `mode("append")`. [C39:L8-9 (file L485)](#c39-l8-9) ✓
- Customer identification precedence order is strictly AR overrides (`c_ov`), reference match (`c_ref`), then payer name match (`c_nm`). [C14:L2-6 (file L137)](#c14-l2-6) ✓
